# The complete set of OSV advisory ids waived in osv-scanner.toml. One id per line, sorted.
#
# WHY THIS FILE EXISTS, IN A DIRECTORY OF EXPECTED OUTPUTS.
#
# `security / osv` is a required, blocking CI job, so every `[[IgnoredVulns]]` entry in
# osv-scanner.toml is a deliberate hole in a supply-chain gate. Two controls already constrain one:
# TestOSVConfig_EveryIgnore_HasReasonIssueAndExpiry refuses an entry without a filed issue and a
# real expiry date, and osv-scanner itself stops honouring the entry once that date passes.
#
# Neither of those requires a HUMAN to agree the reason is a good one. That is what this file adds.
# It is under test/golden/, which is CODEOWNERS-protected (`/test/golden/ @prokopto-dev`), and
# TestOSVConfig_WaiverSet_MatchesTheOwnedGoldenFile fails when it disagrees with osv-scanner.toml.
# So adding a waiver is no longer an edit to one unowned file — it also requires an edit here, which
# requests a code-owner review, and which AGENTS.md separately forbids doing "to go green".
#
# It is second-best on purpose. Owning osv-scanner.toml directly in .github/CODEOWNERS would be more
# direct, and that one-line change is staged for the maintainer (see PR #152). This achieves the same
# property through the ownership surface that already exists, so the gate is not left unguarded while
# waiting for it. If the CODEOWNERS entry lands, keep this too: two independent locks on a waiver
# list is defence in depth, not duplication.
#
# TO CLEAR A WAIVER: fix the dependency, run `make osv-scan`, then delete the id from BOTH
# osv-scanner.toml and this file, and close the tracking issue. Deleting from one is a red build.
#
# THE LIST WAS EMPTY UNTIL #273, and the difference between the one id below and the three before it
# is worth stating. Those three — GHSA-xffm-g5w8-qvg7 (#133), GHSA-g7r4-m6w7-qqqr (#134) and
# GHSA-5p4m-2wfm-xmqj (#135), from the first scan of web/pnpm-lock.yaml this repository ever ran —
# were REAL findings in transitive devDependencies, waived while a fix was pending and cleared by the
# dependency bump that closed those issues, ahead of their 2026-11-09 expiry.
#
# GO-2026-5932 is not that shape. It is a permanent advisory about golang.org/x/crypto/openpgp, a
# package no build graph in this repository contains, attached to a module that is here for argon2id
# (03-security.md §3.1). There is no version that fixes it and no fix to wait for, so its expiry
# forces a re-check of the only fact that could make it wrong — that nothing has started importing
# openpgp — rather than a fix. osv-scanner.toml carries the evidence; #280 tracks it.

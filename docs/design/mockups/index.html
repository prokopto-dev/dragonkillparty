Dragon Kill Party · design reference

Five surfaces, fifty-five screens.

DKP and guild management for Project 1999 EverQuest raiding guilds — one Go binary, one SQLite file, an embedded React SPA, run by volunteer officers. These pages are the design target the implementation is being built against.

MOCKUP

Every number, name and date on these pages is a fixture. Nothing is connected to a server, almost nothing is clickable, and the product is not finished — the repository is still in its foundation phase. Treat these as a specification of intent, not a demo.

What these settle

They exist to answer interaction and vocabulary questions before implementation, so an officer's workflow is designed once rather than re-derived per screen. Where the project's documents were explicit the mockups follow them; where the documents were silent the mockups invented something, and every invention is catalogued with a verdict.

Known to be wrong

  • A single instance-wide seq is printed across pools. A sequence is allocated per pool; an as-of marker is only meaningful inside one.
  • Any three-figure main-tier bid predates tiered bidding. Mains only compete with mains, so those bids land in single or low double digits.
  • Money is formatted three different ways. The product formats it once.
